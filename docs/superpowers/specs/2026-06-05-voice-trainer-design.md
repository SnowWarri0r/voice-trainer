# Voice Trainer — 音高与共鸣实时反馈工具 设计文档

**日期**: 2026-06-05
**状态**: 设计已确认,待生成实现计划

## 1. 目标与范围

做一个对**嗓音训练**提供客观反馈的工具:让用户在说话时知道自己的**基频(F0)**和**共振峰/共鸣**是否落在目标区间内("在区=对 / 出区=错")。

之所以选这个场景:目标最硬、最可量化——基频有可配置的参考区间,共鸣可由共振峰测量。机器能给出可靠的"在区/出区"判断,这是 F0+共振峰反馈最经典的落点。

**反馈节奏**:实时(边说边看)+ 录制复盘,分阶段实现。
**平台**:Web 前端 + Python 后端。
**目标带来源**:内置参考带 + 可自定义(标定或手动调)。

### 诚实边界
- **可测量层**(基频、共振峰、归一化共鸣、抖动)给的"对/错"可靠,可放心当真。
- 不做"音色好不好听""技术健不健康"这类审美判断——这层连人类老师都无公论,本工具不涉足。

## 2. 架构

三块,边界清晰、各自单一职责、可独立测试:

1. **Web 前端(浏览器)**:WebAudio 采麦克风 → 切 ~30ms PCM 块 → WebSocket 流给后端;收回分析结果后渲染界面。**只管 UI / 采音 / 画图,不做信号处理。**
2. **Python 后端(FastAPI)**:
   - 一个 **WebSocket 端点**吃音频流,逐块调分析引擎,实时推回结果。
   - 一个 **HTTP 端点**收录制好的整段音频,批量分析出高精度复盘报告。
   - 同时**托管前端静态产物**(部署时单进程单端口)。
3. **分析引擎(后端内的纯函数库)**:一份代码,实时和复盘共用,保证两者口径一致——实时指针和最终报告永不打架。这是"音频流给后端算"这个选择换来的核心好处。

### 关键技术决策
- **实时计算放后端**(经 WebSocket 流式)。代价:几十毫秒往返延迟(本机无感)+ 流式处理复杂度。收益:实时与复盘单一引擎、口径一致。
- 共振峰需要比 30ms 更长上下文,后端**按会话维护 ~50ms 滚动缓冲**,每来一块分析最新窗口。

## 3. 模块边界

### 后端
- `analysis/` — 纯 DSP 函数库。输入一段 PCM,输出 `{f0, f1, f2, vowel, resonance, confidence}`。**不碰网络、不碰状态。** 重点测试对象。
- `realtime_ws` — WebSocket 会话:收流、维护滚动缓冲、调 `analysis`、推结果。只管流转与会话状态。
- `report_http` — 录制复盘:整段音频 → 批量调 `analysis` → 算统计(均值/中位/区间/在区占比/抖动 jitter/shimmer)→ 返回 JSON 报告。
- `targets/` — 目标带读写:内置参考带 + 用户自定义,存本地单文件(JSON 或 SQLite),无需独立数据库。

### 前端
- `capture` — 麦克风采集 + 分块 + WS 收发。
- `realtime-view` — B2 双模式实时界面(见 §5)。
- `report-view` — 复盘报告渲染。
- `target-settings` — 目标带查看 / 标定 / 手动调。

## 4. 数据流

- **实时**:麦克风 → 30ms PCM 块 → WS → `analysis`(基于滚动窗)→ `{f0, f1, f2, vowel, resonance, in_target}` → WS 回 → 前端渲染。
- **复盘**:点录制 → 前端缓整段 → 停 → POST 整段音频 → `analysis` 批跑 → 统计报告 JSON → 前端渲染报告。
- **目标带**:启动读 `targets`(默认内置激活)→ 实时与复盘都引用当前激活 profile 判"在区";设置页可标定/手调并存盘。

## 5. 实时界面:B2 双模式

实时反馈分两种练法,一个工具都覆盖:

### 连读模式(日常主屏)
**音高 + 归一化共鸣双轨**,随时间向左滚动(心电图式),目标带为绿色横条,在区绿、出区红。

- 上轨:音高曲线 vs F0 目标带。
- 下轨:**归一化共鸣**(见下)的一维曲线,而非原始共振峰。

### 单元音模式(慢练 / 定标)
切到 **F1×F2 共鸣定位图**:一个点代表当前音色位置,目标是一圈虚线区域,练"把点挪进圈"。

> **设计依据**:原始 F1×F2 图本质是"元音图",点会因①共鸣变化 ②念不同元音 双重移动。连读时换字会让点满图乱跳,只有持续发单个元音时才干净。所以定位图只用于单元音慢练(它的主场),连读练习用归一化的一维共鸣。

### 归一化共鸣(连读能练的关键)
对识别出的元音 v,取它的中性模板共振峰,算当前共振峰相对模板"整体抬升了多少",压成一个标量映射到"亮↔暗"轴。这样**换元音不影响这个数**,任何说话内容都能练。

## 6. 分析引擎细节

- **基频 F0**:autocorrelation / YIN 类(parselmouth `to_pitch` 或 librosa pyin),对滚动窗每块算一次。
- **共振峰 F1/F2**:LPC(parselmouth Burg 法),基于会话滚动缓冲的最新窗口。
- **元音识别**:由 (F1,F2) 最近邻匹配元音模板质心。默认通用模板,标定后用用户个人模板。
- **归一化共鸣**:见 §5。需**一次性标定**——录几个持续元音设定个人元音模板。标定同时建个人模板与目标带,与"目标来源=自己标定"打通。

## 7. 目标带数据模型

```
TargetProfile {
  id, name,
  f0_min, f0_max,                  # 基频区间 (Hz)
  resonance_min, resonance_max,    # 归一化共鸣区间
  vowel_templates: { a:{f1,f2}, i:{f1,f2}, u:{f1,f2}, ... },  # 标定后填充
  source: "builtin" | "calibrated" | "manual"
}
```

- 内置 1–2 个默认 profile(可配置的参考区间)。
- 用户可标定生成新 profile,或手动拖动改区间。
- 存后端本地单文件(JSON / SQLite),无需独立数据库。
- 实时与复盘都引用当前激活 profile 判"在区"。

## 8. 错误处理

全部退化成对用户有意义的状态,不报红崩:
- 没声音 / 太轻 → "听不到,说大声点",不画噪声点。
- 清音 / 无基频(s、f 等)→ 标"无音高",不算跑调。
- 共振峰置信度低(LPC 不稳)→ 点变灰,不误判。
- WebSocket 断 → 前端自动重连,UI 显示"重连中"。
- 麦克风权限拒绝 → 明确引导开权限。

## 9. 测试

- `analysis/` 纯函数:喂固定音频片段,断言 F0/F1/F2 在容差内 → 重点覆盖。
- 几个已知元音的合成/真实样本当回归集。
- WebSocket 与 report 端点各一条端到端冒烟测试。

## 10. 工程化

- **单文件夹**:`voice-trainer/` 一个仓:
  ```
  voice-trainer/
    backend/        # Python / FastAPI(analysis, realtime_ws, report_http, targets)
    frontend/       # Vite(capture, realtime-view, report-view, target-settings)
    Makefile
    Dockerfile
    compose.yaml
    docs/
  ```
- **一条命令本地起**:`make dev` —— 同时拉起 uvicorn(后端热重载)和 vite(前端热重载,WS 代理到后端)。一行搞定,不开两个终端。
- **一键部署**:多阶段 `Dockerfile`——先 build 前端静态产物,塞进 Python 镜像,FastAPI 同时托管静态前端 + API/WS,最终单进程单端口。部署 = `docker compose up -d`(或 `docker run` 一行)。parselmouth 走 pip wheel,镜像里不装系统级 Praat,保持干净。

## 11. 分阶段落地(YAGNI,先能用)

- **阶段一(MVP)**:采音 → WS → 后端 F0 + 共振峰 → B2「连读双轨」(音高 + 归一化共鸣)+ 内置目标带。`make dev` 跑通。
- **阶段二**:单元音定位图模式 + 标定流程(建个人元音模板 / 目标带)。
- **阶段三**:录制复盘报告(Praat 高精度统计)+ Docker 一键部署打磨。
